- section 6 numbers: the final render uses the verified `research/results/movie_facts.json` (the merged 1x1..5x5 exhaustive sweeps, 4,730,000 random boxes up to 512x512, 3,484,889 adversarial runs), so the section-6 rules give LONGEST_ONSET = 1,323,594 (random k=512, p=0.5, seed 20260921, sample 9269; 130,511 black cells; re-simulated and asserted in-render) and TOTAL_TESTED = 41,835,387 (= `total_runs_all_experiments`, cross-checked; the loader aborts on a mismatch). The storyboard's "expected" 466,066 / 196,974 predate those results. `facts_provisional.py` remains only as the fallback for the case that the verified file is absent.
- section 6 schema: the verified file does not use the section-6 field names; `common.adapt_verified_schema` maps them explicitly (`exhaustive.kN` -> `N`, `n_cap` -> `cap_hits`, `exhaustive.4.histogram_log_bins` and `k4_records_csv` read from the result file named by `exhaustive.source` as section 5 says, `random.longest_config` = the (k, p, seed, sample_index, n_black) tuple parsed from `random.longest_config_summary` and regenerated with the exact randexp splitmix64, `random.max_k` = the largest k of any random sweep table, `adversarial.n_tested` <- `total_runs`). Nothing is invented; a field that stays missing still aborts by name.
- section 6 `{LONGEST_SOURCE}`: caption format is `index 9269 · 512x512 · p=0.5` for a random source (the sample index, not the seed; the storyboard example said "seed 4491"), `evolved · 12x12 box · 11 cells` for an adversarial source and `KxK box · pattern N` for an exhaustive source.
